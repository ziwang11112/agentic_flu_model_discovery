# Benchmark-Level Conformal Calibration Report

## Scope

This report summarizes the benchmark-level conformal calibration work added on top of the probabilistic influenza forecasting pipeline.

The purpose of this phase was not to improve point forecasts. Point forecasts for `deterministic_seir`, `probabilistic_seir`, `fractional_seir`, and `constrained_structure_discovery` were left unchanged. The goal was to improve the reliability of probabilistic intervals through benchmark-level post-processing.

## What Was Implemented

The repository now supports benchmark-level uncertainty post-processing through:

- raw intervals
- level-specific scale calibration
- conformal absolute calibration
- conformal standardized calibration
- conformal asymmetric calibration

The implementation is benchmark-level rather than series-local:

- raw probabilistic forecast artifacts are generated by the main benchmark run
- validation and rolling-origin residuals are collected into a residual bank
- multiple calibration kinds are evaluated on validation and test splits
- winner selection uses validation rows only
- test rows are evaluation-only

The benchmark now keeps fitting-time interval calibration disabled when benchmark-level conformal postprocessing is enabled, so the conformal layer always operates on raw probabilistic artifacts rather than doubly calibrated intervals.

Main code paths:

- uncertainty postprocess core: [`src/uncertainty/`](../src/uncertainty)
- benchmark postprocess script: [`scripts/run_conformal_postprocess.py`](../scripts/run_conformal_postprocess.py)
- upstream benchmark artifact support: [`src/evaluation/pipeline.py`](../src/evaluation/pipeline.py)

## Selection-Rule Comparison

Three winner-selection rules were compared over the same benchmark outputs.

### V1

Rule:

- keep methods with `coverage_gap >= -0.05`
- then minimize `interval_score_mean`
- then minimize interval width

Aggregate selected-test summary:

- mean absolute coverage gap: `0.189394`
- mean interval score: `0.460618`
- mean interval width: `0.451670`

This rule over-favored low interval score and often selected methods that remained over-covered on test.

### V2

Rule:

- minimize `abs_coverage_gap`
- then minimize `interval_score_mean`
- then minimize interval width

Aggregate selected-test summary:

- mean absolute coverage gap: `0.183838`
- mean interval score: `0.484247`
- mean interval width: `0.473100`

This improved coverage alignment slightly, but at the cost of wider intervals and worse interval score.

### V3

Rule:

- first filter out methods with `coverage_gap < -0.05`
- then minimize `normalized_abs_coverage_gap + 0.25 * normalized_interval_score`
- then minimize interval width

Aggregate selected-test summary:

- mean absolute coverage gap: `0.184343`
- mean interval score: `0.465319`
- mean interval width: `0.456298`

## Recommended Rule

`V3` is the current recommended winner-selection rule.

Why:

- it keeps the coverage behavior close to the better coverage-first rule
- it avoids most of the interval-score degradation seen in `V2`
- it is materially more balanced than both extremes

The current view is:

- `V1` is too interval-score-driven
- `V2` is too coverage-gap-driven
- `V3` is the best compromise so far

From [`artifacts_v5_conformal_v3/calibration_method_winners.csv`](../artifacts_v5_conformal_v3/calibration_method_winners.csv):

- `0-4 yr`: `conformal_asymmetric` for `50/80/95`
- `18-49 yr`: `scale_calibrated` for `50`, `conformal_asymmetric` for `80/95`

- `>= 65 yr`: `scale_calibrated` for `50/80`, `conformal_absolute` for `95`

Winner counts:

- `conformal_asymmetric`: `7`
- `scale_calibrated`: `6`
- `conformal_absolute`: `4`
- `conformal_standardized`: `1`

## Interpretation

The results do not support a single universally best calibration kind.

Instead:

- lower-confidence intervals often favor asymmetric or scale-based correction
- 95% intervals often favor absolute conformal calibration
- age group matters
- benchmark-level validation-based selection is useful, but the choice of selection rule meaningfully changes conclusions

This is consistent with the broader project finding that age-aware selection is more valuable than searching for a single globally best model family or a single globally best interval-adjustment rule.

## Practical Recommendation

For the current repository state:

1. treat `artifacts_v5_conformal_v3/` as the recommended Phase 2 conformal result set
2. keep point forecast recommendations unchanged
3. use the benchmark-level conformal postprocess only for uncertainty calibration
4. treat `V3` as the current default winner-selection rule unless a later experiment shows a clearly better tradeoff

## Reproduction

First rerun the benchmark so that leakage-free probabilistic validation artifacts exist:

```bash
python run_experiment.py --config configs/age_robustness.yaml --log-level INFO
```

Then run the benchmark-level conformal postprocess:

```bash
python scripts/run_conformal_postprocess.py --config configs/age_robustness.yaml --artifact-root artifacts_age_robustness --output-root artifacts_v5_conformal_v3 --log-level INFO
```
